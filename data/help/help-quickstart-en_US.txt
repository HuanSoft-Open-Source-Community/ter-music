ter-music Quick Start Guide
===========================

1. Starting
-----------
  ter-music [options] [path]   Go straight into the TUI
  ter-music tui [path]         Enter the TUI explicitly
  ter-music <command> [options] CLI mode (see section 19)

  TUI options:
    -o, --open <path>  Open a music directory, audio file or remote URL at startup
    -d, --debug        Enable debug logging (ter-music-debug.log)
    -v, --version      Print the version
    -h, --help         Show usage
    --frontend=local   Migration baseline: this process makes the sound itself
                       (the default is remote — playback is left to the core)
    --attach-only      Only attach to an already running core; fail if there is none
    --bus <name>       Target instance bus name (default: the primary instance)
    --lang <lang-id>   Use this language for this run (e.g. zh_CN, en_US, zh-PQ),
                       without saving it to config.xml

  Process model: the default is "resident core + front end". The TUI is only a
  front end; the audio comes from the core process. When no core runs, the front
  end starts one in the background (inside a Linyaps container it requests D-Bus
  activation instead). The core only plays the queue of local paths the front end
  delivers; the library, playlists, favorites, history and remote sources are all
  front-end data. The TUI must run in a real terminal — do not pipe its output.

  Examples:
    ter-music -o ~/Music
    ter-music -o /path/to/song.mp3
    ter-music -o ftp://host/path/to/music/

2. Layout Overview
------------------
  The main view is driven by JSON split trees with six pane kinds:
    playlist / info / controls / spectrum / lyrics / vinyl
  Each layout is a binary split tree: a split cuts its rectangle into two
  children by row (left/right) or col (top/bottom), and a leaf names a pane
  kind. Layouts therefore force-tile the whole main area (the terminal minus the
  bottom menu bar): no gaps, no overlaps. Resizing recomputes the per-mille
  ratios. Old flat-rectangle layouts are still read: guillotine arrangements
  convert exactly; holes, overlaps, out-of-bounds rects and non-guillotine
  arrangements are reflowed in reading order and reported in the reload message
  or the editor instead of being rejected.
  lyrics and vinyl may coexist: when both are in the layout, a track with lyrics
  draws both panes; a track without lyrics makes the lyrics pane step aside (the
  other panes fill its area) and it returns automatically as soon as a track
  with lyrics is playing — no view switch or terminal resize is needed. A
  lyrics-only layout still falls back to the vinyl animation when the track has
  no lyrics (colored blocks when colors are available; the original glyph
  animation otherwise); the fallback skips its spectrum bars when the layout
  already has a dedicated spectrum pane.
  Pane content, including the info-pane album cover, is clipped inside its
  border; a pane too small for its renderer shows only background and border.
  The info pane rearranges itself by size: wide panes keep metadata and audio
  parameters side by side with the cover on the right; narrow-and-tall panes
  stack the cover above the metadata and audio blocks. The cover keeps a blank
  column before the right border and is hidden when the pane cannot give it
  that room.
  Choose: F2 -> Appearance -> UI Layout (←/→ cycles, ENTER opens the list);
  "Reload Layouts" re-reads the files and reports auto-fitted layouts.
  Layout editor: F2 -> Appearance -> Edit Layout / New Layout (edits the split
  tree directly with a live preview; arrows select, Tab cycles, [ ] adjust
  ratios, | / - split, x remove, t change type, c colors, w swap, Enter actions,
  ? help, S save, Esc/q back). Saving writes the user override file — editing a
  preset overrides it by the same id; n renames.
  Presets (7): classic / vinyl / karaoke / visualizer / focus /
               stage / neon
  Built-in: /usr/share/ter-music/layouts/layouts.json (source: data/layouts/)
  User override: ~/.config/ter-music/layouts.json (same id overrides built-in)
  Selection: ~/.config/ter-music/ui-layout (front-end local, not config.xml)
  Terminal light/dark: F2 -> Appearance -> Default Appearance Mode
  (Auto / Light / Dark, stored as preferences.appearance_mode, contract v10).
  In Auto the TUI first asks the terminal for its background (OSC 11); when it
  does not answer, it tries the terminal's own theme on deepin-terminal
  (read-only, refreshed at most every 2s; TERM_PROGRAM is authoritative and the
  ancestor chain is used only when it is unset; other terminals are not
  probed), then the XDG desktop portal color-scheme (followed live), then
  COLORFGBG, a TERM hint, and finally keeps the legacy dark look. The Settings
  row shows the detection source. A per-terminal override (the page's "This
  Terminal's Appearance" row) in the front-end-local
  ~/.config/ter-music/appearance-terminals.json wins over the global default;
  the detected variant is per front end and is never saved to config.xml. On a
  light background factory theme colours and the seven
  built-in presets switch to a light-safe palette; changed colours are kept and
  user layouts only adapt foregrounds that still equal the preset's shipped
  dark value (TER_MUSIC_LAYOUTS is used verbatim). With focus reporting,
  leaving and returning to the window re-detects; otherwise use "Re-detect
  Terminal Background" on the same page.

3. Focus Switching
------------------
  Key          Action
  C            Focus to control bar
  L            Focus to list area
  Tab/Shift+Tab  Toggle file browser / play queue view
  (While lyric seek mode is active, Tab switches the lyric source instead —
   see section 10.)

4. List Area Controls (File Browser or Queue)
----------------------------------------------
  Navigation:
  ↑/↓  or  j/k     Select track up/down
  Enter or Space    Play selected track (on a directory row in the file browser
                    view it expands/collapses instead)

  Playback:
  n                 Next track
  p                 Previous track
  h                 Show the playback history popup (ENTER plays, ESC cancels)

  Queue Management:
  a                 Append track to play queue
  i                 Insert track as next in queue
  d                 Remove track from queue
  D                 Clear the entire queue
  J                 Move track down in queue
  K                 Move track up in queue

  Playlists & Favorites:
  A                 Add to a custom playlist (opens a selection popup; create a
                    playlist in F4 first)
  F / f             Add to favorites
  O / o             Open a music folder
  I                 Append a music folder to the current list

  Search & Browse:
  S  or  /          Search tracks (pinyin supported)
  M                 Toggle the library browser
  + / -             Volume up / down (5% per step)

  Quick Play Modes:
  1                 Sequential
  2                 Single Repeat
  3                 List Repeat
  4                 Shuffle Repeat
  5                 Folder Sequential

  The main view and every sub-view take the mouse (left button and wheel). One
  event has exactly one owner — the popup that is open, or the pane the pointer
  sits in — never two:
    · Bottom function-key bar: a click fires that key's action; the wheel does
      nothing there (the event is still consumed).
    · Playlist pane: a click selects the row and plays that track (in the file
      tree it expands/collapses the directory); the wheel moves the selection one
      row up or down. This works for search results, the play queue and the file
      tree alike, and the wheel never starts playback.
    · Library browser (opened with M, it replaces the playlist pane): a click
      selects the entry and runs it (drills down); the [S]/[R] lines trigger
      scan/rescan; the wheel moves the selection (same as Up/Down).
    · Control bar pane: a click presses the button under the cursor (the Volume
      button and the progress row only take the focus, like the keyboard); the
      wheel on the progress row seeks ∓5 s, on the Volume button adjusts ±5 %,
      on the Speed button steps through the speed presets (wrapping at both
      ends); other buttons do nothing — the Karaoke one included, its level is
      picked from the popup only.
    · Lyrics pane: a click jumps to the line under the cursor; the wheel seeks to
      the next / previous lyric line (it does not toggle lyric seek mode).
    · Info, spectrum and vinyl panes: nothing is defined there, and the event is
      consumed, so it never leaks into another pane.
    · Sub-view sidebar and content area: a click selects the row and runs it
      (same as Enter); the wheel moves the selection within the column under the
      pointer. On the Settings page it follows the section you are in (option
      list, hotkey list, remote device list); on the Equalizer page it only moves
      between bands — the wheel never changes a gain value; on the Help page it
      scrolls one line at a time. The About view's content area is read-only text
      and the Language view's sidebar holds a single "back" entry, so the wheel
      there is only claimed and moves nothing. The highlight follows the pointer:
      scrolling or clicking in the content column also moves the keyboard focus
      there. A double or triple click has no extra meaning — it is treated as
      that one click and never fires twice.
    · While a popup is open (control-bar play mode / speed / volume / karaoke
      menus, the settings option picker, the layout editor's modal menus): the
      wheel scrolls the popup wherever the pointer is; a click inside selects
      that entry and runs it immediately (Enter; Space, i.e. tick the field, in
      the multi-select picker); a click outside only closes the popup — that
      click is swallowed and never reaches the pane behind it. The settings
      picker opens at the option that triggered it (same row, starting right
      after the option's label and colon so the name stays visible) and
      flips/clamps/shrinks at the edges so it stays inside the terminal, clear
      of the status line, bottom hint row, scrollbar and right border.
    · Text input boxes are modal (search, scan directory, layout rename, hotkey
      capture, numeric colour entry): mouse events inside them are ignored, so a
      stray wheel event cannot corrupt the text being typed.
    · Modifier keys change behaviour in exactly one place: Ctrl+left and Alt+left
      open the right-click context menu, but only on terminals that forward
      modifier bits. A plain left click is unaffected. The **middle mouse
      button** (the wheel) opens the same menu without any modifier. Everything
      else is classified by button bits alone: a modified right click or a
      modified middle click is deliberately not claimed and is left to the
      terminal/window manager. Only wheel up/down is requested; the horizontal
      wheel and pointer motion (hover) are never reported to the program.
    · A right click opens a context menu at the pointer: the menu is clamped to
      the screen (it flips up/left at the edges and never covers the bottom hint
      row). The middle button is the reliable alternative on deepin-terminal: it
      forwards middle clicks and does not show its own menu for them. Ctrl/Alt+
      left click only works where the terminal forwards modifier bits —
      deepin-terminal 6.5.40 strips them, so there Ctrl/Alt+left is a plain click
      (it plays), and you should use the middle button. At most one overlay
      exists at a time; while a popup or menu is open a right click (or middle
      click) only closes it and is swallowed — no stacking and no pass-through.
      Inside a menu a left click selects and runs that entry; the wheel moves the
      selection and submenus open to the side; Up/Down/Enter/Esc/Right work from
      the keyboard, any other key closes and swallows. The list pane menu covers
      queue management, favourites, add to playlist, folder/search/play history,
      playback controls and page navigation, and always includes "switch the list
      pane between file and queue mode"; a right click never plays the row. Every
      sub-view (Settings, History, Playlist, Favorites, Help, Language) has its
      own page menu; the Info page has only the Konami aurora entry; the layout
      editor opens its pane-actions menu on right click. If a queue/history/library
      row changes after the menu opened, row actions report "the list changed;
      please try again" and do nothing.
      When a repainting lyrics/spectrum/vinyl pane overlaps the menu, the pane
      refresh is composed with the menu backing and flushed once, so the menu
      rectangle is never erased.

5. Control Bar (when focused with C)
-------------------------------------
  ←/→              Select control button
  Space             Activate selected button / open popup menu
  ↑/↓               Adjust volume while the [Vol] button is selected
  ,                 Seek backward 5 seconds
  .                 Seek forward 5 seconds
  +/=               Increase volume
  -/_               Decrease volume
  Ctrl+L             Toggle lyric seek mode; ↑/↓ then jumps line by line to each
                     lyric timestamp

  Control Buttons:
  [<<]       Previous track
  [>||]      Play / Pause
  [>>]       Next track
  [Stop]     Stop playback
  [Mode]     Play mode (the popup lists the modes currently available)
  [Speed]    Playback speed (popup: 0.75x / 1.00x / 1.25x / 1.50x / 2.00x / 3.00x)
  [Vol]      Volume popup (0-100, 5% steps)
  [Karaoke]  Vocal-removal popup (Off / Faint vocals / No vocals; stereo only;
             per-bin centre removal in 200 Hz-5 kHz keeps pan-spread and
             hard-panned transient content; level changes ramp smoothly)
  [Progress] Current playback progress

6. Play Modes (17 in total)
-------------------------
  Basic modes (always available, 5):
    Sequential      Play through the list, stop at the end
    Single Repeat   Repeat the current track
    List Repeat     Repeat the whole list
    Shuffle Once    Shuffle, play each track once
    Shuffle Repeat  Continuous shuffle

  Folder modes (4, offered in the file browser view):
    Folder Sequential / Repeat / Shuffle / Shuffle Repeat — scoped to the
    current directory

  Advanced modes (8, require album and artist tags in the SQLite library):
    Album Sequential / Repeat / Shuffle / Shuffle Repeat
    Artist Sequential / Repeat / Shuffle / Shuffle Repeat

  Press Space on the [Mode] button to open the popup menu.
  Pick the default mode and enable "Advanced Play Modes" in Settings -> Play Mode.

7. Function Keys (F1-F9)
-------------------------
  F1  Home (return to the main view)
  F2  Settings (appearance/layout, path, playback, play mode, hotkeys, remote
        devices, equalizer, info display)
  F3  Folder history (music folders you opened: ENTER loads, A appends to the
        queue, D removes the entry, C clears all)
  F4  Playlists (manage and create playlists)
  F5  Favorites (view and manage favorite tracks)
  F6  About (version and project info)
  F7  Language (language manager: ENTER switches, A adds a pack, D deletes;
      built-ins: zh_CN, en_US, zh-PQ)
  F8  Help (this page; / searches, ↑/↓ scroll)
  F9  Quit the front end (stop_core_on_exit = 1 is the default, so the core
      stops too; only with 0 does playback continue in the background — see
      section 20)
  ESC followed by 1..9 equals F1..F9; q / Q takes the same exit path as F9.

7.1 Custom Keybindings
-----------------------
  Settings -> Hotkeys is an editable action list:
    ↑/↓            Select an action
    Enter/Space    Capture a new key (Esc cancels)
    r              Restore the selected action's default key
    R              Restore all defaults
    s              Save (writes config.xml; changes stay in memory until then)
    ←/Tab          Back to the menu sidebar

  Every action except the system-reserved keys can be rebound:
    - F1-F9: view/quit function keys
    - q / Q: quit
    - Tab / Shift+Tab: file/queue tab switch
  The reserved actions are hidden from the settings editor. Playback, list/queue,
  library browser, settings, remote devices and all other view actions are
  editable.

  Key syntax (case-sensitive):
    x, A, 7, /        One ASCII printable character (space must be "space")
    ctrl+a            Ctrl+letter; c/h/i/j/m/z are reserved by the terminal
    up down left right home end pgup pgdn ins del backspace tab btab enter space
    f1 ... f12        Named special keys
    Esc and Ctrl+C are system keys and cannot be rebound.

  Only changed actions are written to config.xml, for example:
    <keybindings>
      <binding action="track.next" key="]"/>
      <binding action="track.prev" key="["/>
    </keybindings>
  The action IDs are the stable strings printed by `ter-music keys list`.
  Overrides for reserved actions are ignored at runtime and reported as warnings
  by `ter-music keys check`; Config.Set rejects new bindings for them.
  A conflict inside the same context is rejected: the message explains why and
  the previous binding stays. Rebinding an action drops all of its default
  aliases, so only the new key remains.
  Not supported: Alt combinations, multi-key sequences (such as gg) and
  non-ASCII keys. Bindings apply immediately and survive a restart.

8. Library Browser (M)
------------------------
  Press M to enter/leave the library browser. Its data is the front-end library
  (library.db); without a database M does nothing.
  Home menu (4 entries): Artists / Albums / Genres / All Tracks — ↑/↓ selects,
  Enter or Space enters.
  Hierarchy: Home -> Artists -> Albums -> Tracks; Home -> Albums -> Tracks;
             Home -> Genres -> Tracks; Home -> All Tracks.
  In a track list:
    ↑/↓          Select track
    Enter/Space  Play the selected track (it is appended to the current list
                 first when missing, then the browser closes)
    a / A        Append the selected track to the current playlist
    ESC          Go back one level (at Home it leaves the browser)
  Extra Home keys: S/s scan a directory, R/r rescan all roots, M or ESC leaves.

9. Search
----------
  Press S or / in the main view to enter search mode.
  Type keywords, Enter to filter results.
  Navigate with ↑/↓, Enter to play.
  Press Esc to cancel (an async search in progress is aborted).
  Supports pinyin search (e.g., "zhou" finds "Jay Chou").

10. Lyrics
-----------
  Priority order: embedded lyrics (FFmpeg/APE) > .lrc file > no lyrics
  (vinyl animation in the lyrics pane — colored blocks when colors are available;
  the separate spectrum pane keeps showing the audio-reactive bars)
  .lrc files in the same directory are loaded automatically.
  Embedded lyrics (in ID3/APE tags; keys such as lyrics, lyrics-eng,
  UNSYNCEDLYRICS and ©lyr) take priority when available.
  Ctrl+L enters/leaves lyric seek mode: ↑/↓ moves the cursor and seeks to that
  line's timestamp.
  It works in both front-end modes — the seek goes through the player facade to
  the core instead of a local progress tracker.
  Switch between embedded/external: Ctrl+L then Tab (in lyric seek mode); the
  preference is recorded by the front end in its own library.
  Lyrics visibility comes from the layout preset (not a config toggle); alignment can be left, center or right in Settings -> Appearance.

11. CUE Split-track Support
----------------------------
  A .cue sheet named like the audio file is parsed automatically (typical for
  FLAC/APE/WV image files).
  Sub-tracks appear with a [CUE] prefix in the playlist.
  CUE file encoding is auto-detected (Settings -> Playback):
    Auto / UTF-8 / GB18030 / GBK / BIG5 / Shift-JIS

12. Equalizer
-------------
  10-band ISO graphic equalizer (31Hz - 16kHz).
  Tune it in the Settings -> Equalizer section: ←/→ selects a band, ↑/↓ changes
  the gain (±12dB), ENTER toggles the master switch; pre-amp is also ±12dB.
  Press P to open the separate "EQ Preset" popup (Rock, Pop, Classical, Jazz,
  Electronic, Vocal, Bass Boost, Live, Balanced, Flat — 10 presets). A preset
  changes band gains only and keeps the pre-amp.
  The output stage uses tanh soft clipping, so stacked boosts do not wrap around.

13. Remote Playback
-------------------
  Remote sources are handled by the front end: it lists a remote folder,
  downloads its tracks into a local cache, and hands those cached local paths
  to the core. The core plays local files only.

  Protocols: SMB, SFTP, FTP, WebDAV and HTTP; FTPS and HTTPS are the TLS forms
  of FTP and HTTP. SMB uses the external `smbclient` program, so install the
  Samba client; without it SMB connections report that smbclient is missing.

  Configure a connection in Settings -> Remote Devices (F2, sixth Settings
  item). Fields: name, protocol (SMB/SFTP/FTP/WebDAV/HTTP; +/- cycles), host,
  port (empty = the protocol default), username, password, base path,
  plus protocol-specific fields:
    - HTTP/WebDAV/FTP: TLS (https/webdavs/ftps) and, when on,
      "trust self-signed certificate";
    - SFTP: private key, key passphrase, known_hosts path.
  The base path is required ("/" = server root). For SMB enter the share and
  an optional subfolder, e.g. "music/albums" - not an smb:// URL. A folder
  path or URL does not need a trailing slash; the front end adds it when
  listing. TLS is a per-connection switch, not a port rule: an HTTPS server on
  port 8443 needs TLS on and the port set to 8443.
  ENTER edits a field, +/- changes the protocol/TLS switch, S saves and ESC
  cancels. A port outside 1-65535 or an empty base path cannot be saved.
  Deleting a connection asks for confirmation (ENTER deletes, ESC keeps it).

  SFTP verifies host keys and fails closed: a readable known_hosts file (the
  connection field, otherwise ~/.ssh/known_hosts) must already contain the
  server. There is no automatic trust on first use; add the key first with
  ssh-keyscan HOST >> ~/.ssh/known_hosts.

  Connection menu: Browse Folder, Load to Playlist, Refresh Connection, Edit
  Connection, Delete Connection. In the folder browser, up/down selects:
  ENTER enters a selected folder (on the first row, or on a file, it loads
  the current folder), RIGHT also enters the selected folder, ESC goes up a
  level.
  Opening a folder downloads its audio files (files directly in that folder,
  not subfolders) into the cache, up to 200 tracks per open; a larger folder
  reports how many of how many tracks were loaded. Downloads run in the
  background: the page shows "Downloading done/total, failed n" and the main
  status bar shows the same; ESC cancels the running job. The menu offers
  "Cancel current job", "Retry listing" and "Retry failed tracks (n)".

  Limits: one remote file may be at most 1 GiB, one directory listing at most
  32 MiB (200,000 entries); connect times out after 10 s, listing after 120 s
  and each download after 600 s. An oversized file is skipped and the other
  tracks continue. SMB file names containing ';', '!', double quotes,
  backslashes or control characters are refused (smbclient command mode);
  rename them on the server. Downloads are on demand; there is no prefetch.

  Cache: $XDG_CACHE_HOME/ter-music/remote/ (default
  ~/.cache/ter-music/remote/). Remote Devices shows its size and can set a
  limit (default 2048 MB, 0 = unlimited) or clean unprotected files; tracks
  that are playing, queued, favorited or in the history are kept. A .lrc
  beside an audio file is cached with it.

  Credentials: the connection list is the front-end file remote.xml
  (mode 0600); passwords are obfuscated with a fixed-salt XOR stream, not
  encrypted. Logs, the core's last_opened_path and the library folder history
  store a redacted URL, so a URL read back from history has no password; use
  the saved connection for password-protected servers. Do not put
  user:password@ into an ad-hoc remote URL - it stays visible in the shell
  history and process list.

  A remote URL can also be opened directly by the TUI:
    ter-music -o webdav://host/music/
  Accepted schemes: http(s), ftp(s), sftp, smb, webdav(s) (dav/davs are
  aliases); the scheme is case-insensitive.
  CLI `play` and `daemon start --open` reject remote URLs: the core only plays
  local paths.

  Automated coverage: HTTP/WebDAV/FTP, the FTPS TLS handshake, HTTPS on
  non-443 ports, self-signed CA trust, 401/404, slow-download cancellation,
  and SMB through a fake smbclient. A real Samba server, a real SSH server and
  the FTPS data channel are not covered.

14. Playlist Management
-----------------------
  Press F4 to open the playlist manager.
  Create, rename, and delete playlists.
  Press A (uppercase) in the main view to add a track to a custom playlist.

15. Favorites
-------------
  Press F/f on a selected track to add to favorites.
  Press F5 to view and manage your favorites.

16. Album Art
-------------
  The controls-pane cover follows Settings -> Playback "Album Cover".
  The info-pane cover also has its own "Show Cover" switch in Settings ->
  Info Display; both must be on for the pane cover to appear.
  The CLI/D-Bus text cover can be braille, ASCII or half blocks. The TUI
  info/controls cover uses colored half-block characters (automatic 256→8→
  monochrome fallback) so its glyph width matches the terminal cell grid.
  Color mode composes the two halves with `▀` (foreground = upper half,
  background = lower half); `█` is only used by the monochrome fallback.
  The standalone vinyl pane draws a colored half-block disc, a rotating circular
  album-cover center label and colored spectrum bars (the label follows the same
  256→8 fallback). Without colors, ASCII, or with a tight color-pair budget it
  keeps the original glyph animation; a missing cover leaves the disc and bars
  colored with a plain center.
  Embedded artwork is preferred; otherwise common same-directory files are used
  (cover/folder/front/album with jpg/jpeg/png/webp extensions).
  The character art is generated on demand: on a track change the D-Bus
  CoverChanged signal only announces "the cover changed" with an empty text
  argument, and the actual art is fetched via Info.GetCoverArt (cached per size).
  With D-Bus enabled the cover is also published as mpris:artUrl so desktop
  media widgets can display it.
  The CLI can print the current cover directly:
    ter-music cover [--width --height --charset]

17. Info Pane & Audio Backend
-----------------------------
  The info pane shows state/mode, current-track metadata, the character cover,
  and the current audio technical info (its placement is defined by the layout
  preset):
    Sample Rate, Bit Depth, Bitrate, Codec
  Its rows follow the Settings -> Info Display field mask: the pane uses only
  the fields it can display (state/mode/title/artist/album/queue/format),
  compacts when fields are disabled, and drops the audio block when `format` is
  off. index/path/volume/speed are CLI/D-Bus only.
  It switches between a side-by-side arrangement and a stacked one (cover on
  top) depending on the pane's own width and height. The TUI cover is drawn with
  colored half-block characters (not braille; automatic 256→8→monochrome
  fallback) to keep glyph widths aligned with the cell grid; `ter-music cover`/
  Info.GetCoverArt still honour the configured charset.

  Audio backend auto-detection priority: PipeWire > PulseAudio > ALSA
  Switch it manually in the Settings -> Playback "Audio Backend" entry:
    Auto, PipeWire, PulseAudio, ALSA (applies on next startup)
  The "Latency" entry opens a 20–250 ms popup; it takes effect on next playback.

  Settings -> Info Display: preset, fields and cover also drive the main info
  pane; cover size/charset, progress style and lyric lines affect only
  `ter-music show` and the D-Bus Info.GetDisplay/GetInfo output. Fields marked
  "CLI only" never affect the TUI pane.

18. Configuration & Data
-------------------------
  Layouts:  built-in <prefix>/share/ter-music/layouts/layouts.json;
            user override ~/.config/ter-music/layouts.json;
            selection ~/.config/ter-music/ui-layout (front-end local).
            show_lyrics_panel is deprecated and only seeds the first choice
            when ui-layout does not exist.
  Config:   ~/.config/ter-music/config.xml, written only by the core (the XML
            root version attribute carries the config contract number,
            currently 10; legacy "2.2" files still load and are rewritten with
            the number by the migration on the first upgrade run).
            appearance_mode lives under <preferences> (0 auto, 1 light, 2 dark);
            the detected light/dark variant is per front end and is never saved.
            A front end changes its own mirror and sends the difference via
            Config.Set.
  Content:  ~/.config/ter-music/library.db, the front-end SQLite library: track
            metadata, scan roots, play history, favorites, playlists and their
            tracks, folder history and the temporary playlist.
  Queue:    There is no queue.txt any more. The front end scans content and
            delivers the play queue in chunks (at most 500 entries per call: the
            first Queue.Set, the rest Queue.Append); the core never persists a
            queue, and the front end re-delivers the whole list after a reconnect.
            The resume cursor comes from the resume session fields, not from a
            queue file.
  Resume:   The core writes the last track and position to the configuration on
            every track change, and the front end restores from it at startup.
            The switch is the config key resume_last_playback (it is not in the
            settings list); turn it off with
            `ter-music config set resume_last_playback 0`.
  Cover cache is managed automatically under /tmp/ter-music-cover-*.jpg
  (the 10 least-recently-used covers are evicted, everything is removed on exit).

  Migration from v1 (config.json + JSON files) is automatic on first run.

19. Command Line (CLI)
----------------------
  `ter-music help` prints a short overview; help has several levels:
    help | --help | -h              short overview
    help <command>                  first-level details
    help <command> <subcommand>     second-level details
    help all                        complete help
    <command> --help                first-level details (commands that parse
                                    options: play, show, daemon, queue,
                                    config, lyrics, track, cover, keys)
    <command> <subcommand> --help   second-level details
  An unknown help target exits with code 1.

  Help wraps to the terminal width. When stdin and stdout are TTYs and the
  text is taller than the screen, a built-in pager is used: Space/PageDown
  next page, b/PageUp previous page, j/k scroll one line, g/G first/last
  line, q quits. Non-TTY output, TERM=dumb and TER_MUSIC_NO_PAGER=1 print
  the whole text directly, without ANSI escape sequences.

  CLI-local help, errors, tables and hints use this language priority:
    --lang > TER_MUSIC_CLI_LANG > config ui_language > LC_ALL >
    LC_MESSAGES > LANG > zh_CN
  --lang and TER_MUSIC_CLI_LANG may appear anywhere on the command line.
  C, POSIX and an empty locale mean "no preference" and continue with the
  configured ui_language. An uninstalled --lang ID warns and falls back to
  zh_CN. The bodies printed by show/track/lyrics/cover are rendered by the
  core's ui_language; --lang changes only the CLI's own text.

  Every subcommand is a pure D-Bus client that talks to the primary instance
  (daemon or TUI); put `--bus <name>` after the subcommand to address a
  secondary instance.

  Playback control:
    play <path> [--index N] [--mode MODE] [--no-daemon] [--foreground] [--quiet]
      · With a path: this process scans it and delivers the local path queue in
        chunks, then plays. Paths accept ~ and relative forms; pointing at a
        single audio file plays exactly that file.
      · No path, no --index: keep playing the core's current queue
        (Control.Play); it errors out when nothing can be played.
      · No path but --index: load the configured default music folder
        (default_startup_path, else last_opened_path when remember_last_path is
        on), deliver it, then PlayAt(N). N is 0-based and counts entries of the
        loaded content.
      · --mode: applied after the queue is delivered (shuffle-like modes reorder
        the execution order in place).
      · --foreground: this process becomes the foreground core and plays; no
        background instance is created. Refused when a primary instance exists.
    pause | resume | toggle | stop | next | prev
    seek <+secs|-secs|mm:ss|N%>  Relative / absolute / percentage seek
    volume [0-100|+N|-N]          Read or set the volume
    speed  [0.5-3.0]              Read or set the playback rate
    mode   [name|0-16]            Read or set the play mode
    karaoke [off|soft|full|0-2|cycle]
                                  Read or set the vocal-removal level (cycle
                                  steps one level; echoed immediately, applied
                                  along a 30 ms time constant; stereo only; per-bin
                                  centre removal in 200 Hz-5 kHz, soft leaves
                                  it about -8 dB, full removes it — not the
                                  "karaoke" layout preset, not per-character
                                  lyric highlighting)

  Queue editing (acts on the core's play queue):
    queue list [--offset N] [--count N]  Paged listing (count 0 = default 200,
                                         max 1000)
    queue append <path>[,<path>...]       Append local files to the end
    queue insert <pos> <path>             Insert a local file after a position
    queue remove <pos>                    Remove the entry at a position (0-based)
    queue clear                           Empty the queue
    queue shuffle                         Shuffle (current entry first, rest random)

  Configuration (reuses the core Config interface, keys are config.xml names):
    config get [key]              Full JSON, or one value by key
    config set <key> <value>      Write one scalar (cast/clamped per the schema)
    config reload                 Ask the core to re-read the config file
    config reset --yes            Restore all defaults (explicit --yes required)

  Information output:
    show [--json|--watch[=ms]|--one-line|--full|--compact|--preset|--fields
          --cover|--no-cover|--cover-size|--charset|--progress|--no-progress
          --lyrics|--width] [--bus <name>]
                                  Current playback info (as configured in
                                  Settings -> Info Display)
    track                         Human-readable info about the current track
    cover [--width N --height N --charset braille|ascii|half]
                                  Text cover of the current track
    lyrics [--lines N]            Current lyric line context, or the whole timed
                                  document with --lines N

  Key bindings (read-only, no running core required):
    keys list [--json]            Effective keys per action and context
    keys check [--json]           Audit the overrides in config.xml

  Background player:
    daemon start [--open PATH] [--debug] [--force]
    daemon foreground [--open PATH] [--debug] [--force] [--no-autoplay]
        Note: the core scans nothing, --open is only informational; use `play`
        to deliver a queue.
    daemon stop [--force] [--all] | status [--json] | reload
    daemon restart [--open PATH] [--debug] [--force]

  Other: version | --version | help | help all | --help | tui

  Exit codes: 0 success; 1 usage error; 3 no running instance; 4 D-Bus not
  available; 5 the instance refused or the operation failed.

20. Tips & Tricks
------------------
  Press F8 for this help page (/ searches, ↑/↓ scroll three lines).
  Karaoke (vocal removal) has three levels: Off, Faint vocals and No vocals. It
  only attenuates what is centred in a stereo signal, frequency bin by frequency
  bin inside 200 Hz-5 kHz; the accompaniment, the bass and the top end stay put
  (at 100 Hz and 10 kHz the measured loss is at most 0.25 dB), as do pan-spread
  or hard-panned transients, so a hard-panned hi-hat or snare does not release
  the cancellation of the centred vocal. The Faint vocals level leaves the
  centred content about 8 dB down; No vocals removes it. Mono tracks play
  untouched. While enabled it adds the window length minus one sample of
  algorithmic latency (383 samples at 44.1/48 kHz, about 8.7 ms at 44.1 kHz, at
  most 10 ms at every supported rate); turning it on (or seeking while it is on)
  repeats the first few milliseconds once while the analysis window fills, while
  switching between Faint and No vocals does not. Turning it off fades the
  cancellation out over about 0.35 s before the stream is bit-exact passthrough
  again. Three ways to change the level: the [Karaoke] button popup in the
  control bar, Settings -> Playback, or `ter-music karaoke`. Note that "karaoke"
  names two unrelated things here as well - per-character lyric highlighting,
  and the `karaoke` layout preset. The level persists as karaoke_mode (0/1/2)
  in config.xml and returns on restart.
  Press h for the play-history popup; F3 is the folder-history view — they are
  not the same thing.
  Every settings entry opens its option menu with ENTER (no +/- keys needed).
  Settings -> Default Path now holds "Reload Config" and "Restore Defaults";
  ENTER runs them immediately and reports through the status line.
  The UI adapts automatically when the terminal is resized.
  q / F9 / Ctrl+C, SIGTERM and a lost TTY all converge on the same shutdown
  path, which branches on preferences.stop_core_on_exit in the front end's own
  config mirror (read from disk at startup, and the settings page pushes every
  change to the core at once, so the exit path asks the core nothing): 1
  (enabled by default) sends Control.Quit and the core terminates — it persists
  the session/resume state before stopping playback; 0 sends Control.Detach,
  closing only the front end while the core keeps playing in the background.
  Either message is sent only when this front end really attached to the core
  (handshake done, Attach token held); a front end that never attached exits
  without sending anything and leaves the core alone.
  Toggle it via the settings switch "Stop playback process on exit" or with
  `ter-music config set stop_core_on_exit 0`. With several front ends, an exit
  from an attached front end stops the core unconditionally while the option is
  1 (remaining front ends are not counted); local mode (in-process audio) is
  unaffected. To stop a core on its own: `ter-music daemon stop`.
  To make the core exit once the last front end is gone, set
  <preferences><core_exit_when_no_frontend> to 1 in config.xml (this key is in
  neither the settings page nor the Config.Set/`config set` key table). When
  enabled, the core quits 10 s after the last front end leaves.
  If the connection to the core drops, the UI reconnects automatically with
  exponential backoff; press R to restart the core immediately.

21. D-Bus, MPRIS and the Lyrics API
------------------------------------
  The core publishes /org/mpris/MediaPlayer2 on the session bus as
  org.mpris.MediaPlayer2.ter_music, with MPRIS plus the ter-music interfaces
  cn.org.huansoft.ter_music.Info / Control / Lyrics / Queue / Config.
  The handshake reads core.api_version from Info.GetInfo (currently 7; clients
  require at least 7 - the interface namespace moved to cn.org.huansoft.* at
  version 7).

  MPRIS: Rate is a real read/write playback rate (MinimumRate 0.5, MaximumRate
  3.0); LoopStatus and Shuffle perform full play-mode switching; OpenUri answers
  NotSupported (loading content belongs to the front end).

  Lyrics interface:
    Methods: GetLyrics() -> s (A/B line snapshot)
             GetDocument(offset, count) -> s (paged full document)
             SetSource(source) -> b (1 = embedded, 2 = external)
    Signal:  LyricsChanged(s)
    Per-character timing: GetDocument lines carry end/timing/char_total and,
    for karaoke LRCs, a chars[] array; GetLyrics carries char_sung/char_total.

  Read the current A/B lyric snapshot with:
    gdbus call --session --dest org.mpris.MediaPlayer2.ter_music \
      --object-path /org/mpris/MediaPlayer2 \
      --method cn.org.huansoft.ter_music.Lyrics.GetLyrics

  Full specification: see docs/API_DBUS_en_US.md and docs/API_LYRICS_en_US.md
  in the source tree.

22. Linyaps, ll-box and the TUI guard
-------------------------------------
  ll-box <= 2.3.5 can replay bytes it has already written when its cold-start
  forwarder hits a full terminal queue, splicing duplicated output into the TUI.
  ter-music cannot stop that write; inside the container it measures each
  frame's terminal writes (wchar in /proc/self/io) and forces one full-screen
  repaint only on burst or back-pressure evidence or after a terminal resize. A
  bare-mode reset likewise needs that evidence (or a terminal resize), and the
  endwin+refresh fallback stays opt-in (TER_MUSIC_TTY_HARD_RESET=1, off by
  default). None of this runs outside the container, and the guard adds no
  configuration key, setting-page entry or user-visible switch.
  Known limitation: no repaint is scheduled by a timer when there is no
  evidence, so damage in a session with only small frames and a slow reader is
  not repainted proactively and may stay until a terminal resize, a view change
  or new evidence.
  The root fix is upstream: PR #295 is merged into linyaps-box release/2.3
  (merge commit 31ddf04, 2026-11-20) and makes the forwarder consume the bytes
  it already wrote when TryAgain is returned with k > 0; it covers ll-box
  <= 2.3.5. No release contains it yet (the latest is still 2.3.5) and master
  does not carry it, so check that the tag you install contains it and do not
  assume the next release will.
  There is no plan to publish a UAB with the next ter-music Release; UAB
  artefacts are planned to be published after the upstream fix is released.
  TER_MUSIC_TTY_REPAIR_BACKSTOP_MS, an undocumented tuning variable, was
  removed with the timer fallback; it only configured that fallback, so setting
  it now has no effect.
